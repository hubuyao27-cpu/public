# Field Dictionary, Anchor Grammar & Verification Responsibility Matrix

## 1. Anchor Grammar (来源锚点规范)

Every verifiable claim, quantitative number, precondition, and task answer MUST reference one or more anchors generated by `scripts/parse_paper.py` in `source_index.json` and `anchored_paper.md`.

| Anchor Type | Canonical `anchor_id` | Display Format | Scope |
|---|---|---|---|
| Paragraph (Single Doc) | `P001`, `P042` | `[P042 \| p.5 \| S03.2]` | Exact extracted text block |
| Paragraph (Multi-Doc) | `D1-P001`, `D2-P018` | `[D2-P018 \| p.2 \| D2-S02]` | Distinguishes multiple input files |
| Figure Caption | `FIG:Fig. 2`, `FIG:图 1` | `[FIG:Fig. 2 \| p.4 \| S03]` | Figure caption block + page anchor |
| Table Caption | `TAB:Table 1`, `TAB:表 2` | `[TAB:Table 1 \| p.6 \| S03]` | Table title/caption block |
| Numbered Equation | `EQ:Eq. (3)`, `EQ:Eq. (1.2)` | `[EQ:Eq. (3) \| p.3 \| S02]` | Equation line/block with label |

Each `evidence` entry in JSON carries:
```json
{
  "anchor_id": "P012",
  "page": 3,
  "section": "S02.1 Experimental Setup",
  "quote": "Exact short verbatim excerpt from anchored_paper.md"
}
```

## 2. Core Output Fields (`result.json`)

| Top-Level Field | Type | Description |
|---|---|---|
| `case_id` | string | Preserved from `/input/case.json` (`local-case` if absent). |
| `status` | enum | `success` \| `partial` \| `unable_to_determine` |
| `executive_summary` | string | Concise overview aligned to the paper's actual argumentation flow. |
| `task_responses` | array | Explicit answers to every question in `task.md`/`case.json`, each with `evidence` and `boundaries_or_assumptions`. |
| `paper_card` | object | Cross-paper comparison card covering `bibliographic`, `research_question`, `data_or_samples`, `methodology_and_conditions`, `key_findings`, `preconditions`, `conclusions`, `limitations`. |
| `section_summaries` | array | Ordered summaries matching `section_outline.json` (`body_section_ids`), recording `transition_from_prev`, `purpose`, `methods`, `results`, `conclusion`, `key_points`, and `evidence`. |
| `knowledge_items` | array | Deduplicated retrievable items (`concept`, `variable`, `method`, `finding`, `precondition`, `limitation`) with canonical term, aliases/acronyms, statement, preconditions, and anchors. |
| `evidence_index` | array | Deduplicated flat table of all cited anchors + verbatim quotes across the run. |
| `sources` | object | Extracted document metadata, backend used, page-level layout/OCR reports, and warnings. |
| `uncertainty` | object | Explicitly separates `not_reported`, `unable_to_determine`, `conflicts`, `unreadable_pages`, and `visual_figure_or_formula_pages`. |
| `limitations` | string | Honest summary of scope and unverified boundaries. |
| `manual_takeover_points` | array | Actionable list of locations requiring human inspection. |
| `audit_metrics` | object | Quantitative metrics produced by `verify_notes.py`. |
| `change_records` | array | Timestamped stage/checkpoint execution records. |
| `<output_contract fields>` | any | Any additional/custom keys declared in `case.json` `output_contract` are mapped cleanly without blank `null` placeholders. |

## 3. Machine-Verifiable vs. Human-Review Responsibility Matrix

| Dimension / Field | `verification_mode` | What `verify_notes.py` Checks Mechanically | What Requires Human Confirmation |
|---|---|---|---|
| Anchor existence & page match | `machine_verifiable` | `anchor_id` exists in `source_index.json`; `page` equals indexed page | Whether subtle cross-page paragraph breaks split context |
| Quote grounding | `machine_verifiable` | Normalized substring / ellipsis / token-overlap match in cited segment | Context adequacy if excerpt is very brief |
| Quantitative numbers & units | `machine_verifiable` | Digits, decimals, percentages appear in bound segment or same-page pool | Whether unit conversions or derived ratios calculated by reader are accurate |
| Section alignment & order | `machine_verifiable` | Coverage of `body_section_ids` and monotonic sequence index | Semantic fidelity of condensed prose within each section |
| Term deduplication & aliases | `machine_verifiable` | Duplicate `(kind, canonical_term)` and cross-term alias collisions | Whether two similar acronyms truly refer to distinct domain concepts |
| `preconditions` completeness | `human_review_required` (hybrid) | Presence of field and anchor attachment | Domain judgment on whether subtle implicit experimental assumptions were missed |
| `limitations` & `reader_inferred` | `human_review_required` | Explicit `attribution` tag (`author_stated` vs `reader_inferred`) | Scientific validity of reader-inferred methodological weaknesses |
| Plots, figures & garbled equations | `human_review_required` | Flags `empty_or_scanned`, `garbled_text_risk`, and image-heavy pages | Reading un-transcribed numbers from plots/spectra or verifying broken math fonts |
| Internal / cross-doc `conflicts` | `human_review_required` | Checks conflict entries cite both conflicting sources (`source_a`, `source_b`) | Determining which reported value is authoritative or erratum-corrected |
